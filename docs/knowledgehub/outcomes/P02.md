## Accepted Deviation And Flow Verification Summary

1. **Accepted local-dev DB role deviation (`P02-01`):** `KNOWLEDGEHUB_DATABASE_URL` in local development connects as `dev` (`usesuper = True`, with full table grants on `public.collections`). Owner explicitly accepted keeping `dev` for local development on 2026-11-21.
2. **Verified create/delete authorization flow (owner-delegated handover summary, `Task 19`):**
   - **Verified JWT actor:** `verify_jwt_token` in `identity.py` validates HS256 signature, issuer, audience, and finite `exp`, then parses the `name` claim into a nonzero `UUID` (`AuthenticatedUser.actor_id`). Request bodies cannot supply `Id`, `OwnerId`, or `DeletedAt`.
   - **Remote action permission:** FastAPI routes in `main.py` enforce `Depends(require_permission("knowledgehub", 2))` (`ADD`) on `POST /api/knowledgehub/collections` and `Depends(require_permission("knowledgehub", 4))` (`DELETE`) on `DELETE /api/knowledgehub/collections/{id}` via `SystemProto.CheckPermission` before collection persistence runs.
   - **Server UUID & active-owner SQL predicate:** `create_collection` generates `uuid4()` on the server and stores `owner_id=user.actor_id`. `build_soft_delete_collection_stmt` executes an atomic `UPDATE ... WHERE id == collection_id AND owner_id == owner_id AND deleted_at IS NULL` setting `deleted_at=func.now()` and returning uniform `404` if no active owned row matches.
   - **Why guessed UUIDs and hidden UI buttons are not authorization:** Hiding `Đổi tên` / `Xóa` in `KnowledgeHubPage.tsx` (`canEdit` / `canDelete`) is only a UI affordance, and navigating to `/knowledgehub?c=<guessed-uuid>` or sending direct HTTP requests with another user's UUID still fails closed at the backend (`401`/`403` on token/action checks, `404` on owner/active SQL predicates, with no admin ownership bypass).

## Deferred Contracts Handed Off To Following Parts

- **P03 (File Lifecycle & Document Repository):** Every document read, write, download, and registration must resolve through an active, owned collection (`owner_id` + `deleted_at IS NULL`); design explicit coordination/compensation when collection soft-delete races with FileService stage/finalize without physically deleting uncertain originals; replace `DocumentCount = 0` with a real active-document count.
- **P04 (Durable Worker & Job Lifecycle):** Jobs must observe parent collection soft-deletion and cancellation at processing boundaries so deleted collections never publish new document or chunk states.
- **P05 / P07 (Retrieval & Grounded Ask):** Exclude soft-deleted collections immediately after delete commits from all keyword/vector retrieval and new Ask evidence, independent of background cleanup timing.
- **P06 (Embeddings & Vector Deletion):** Implement durable, retryable hard deletion of **all embedding/vector versions** belonging to a soft-deleted collection, with worker fencing so in-flight jobs cannot reintroduce vectors after deletion.
- **P08 (Historical Sessions & Citations):** Explicitly design historical answer/citation retention and rendering after parent collection deletion without re-exposing deleted original files or restricted evidence.
